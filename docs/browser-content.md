# Browser content boundary

`nuschl-content-wasm` runs the existing `nuschl-content` renderer with its image
feature in a dedicated browser module Worker. The UI receives typed text, spans,
code runs, formula source and RGBA pixels. It never inserts received HTML into
the DOM or sends a received URL to a browser image decoder.

The fixed loader imports `content-codec/nuschl_content_wasm.js` and its WASM from
the application's origin. No source-selected URI is fetched. The codec API has
no session, certificate, TLS, device, storage or network import. The Worker glue
receives local job numbers and message/image bytes, without server identity or
conversation metadata. Browser Workers share their origin and are not a
promise of a separate operating-system process. The reviewed glue and browser
runtime remain part of the boundary; this is not native worker confinement.

## API

`ContentService` in `web/app/src/content-service.js` belongs outside the TLS
Worker. Its Promise methods are:

- `render({source, mode}, {signal})`, where mode is `plain`, `legacy` Mumble HTML,
  or previously normalized `marked` text. The result is
  `{marked_text, plain_text, document}`. These are derivatives.
- `encodeImage(Uint8Array, serverMessageLimit, {signal})` returns
  `{html, thumbnail}`. HTML is generated by the shared encoder as a single PNG
  or JPEG data-image element, capped by the caller's server limit. It does not
  forward arbitrary supplied HTML. The thumbnail contains RGBA pixels only.
- `decodeImage(Uint8Array, {signal})` returns one bounded RGBA image block. It
  accepts supplied bytes rather than a URL, path or URI.
- `cancelAll()` revokes pending work; `dispose()` additionally prevents reuse.

Original plain text is retained exactly in `marked_text`/`plain_text`, including
newlines. Legacy normalization uses the same marked representation as native
clients, preserving code spans, safe link destinations and inline data images.
Typed image replies remove the shared renderer's encoded `source` property.
The initial decoded view uses message thumbnail dimensions, not full-resolution
browser image decoding. Formula rendering remains a separate feature; formulas
here carry inert source and TeX only.

## Source authority and asynchronous completion

The SDK must retain original received source and its mode as authority. A
normalized text field or rendered document must never replace authenticated
source bytes in durable history. The content Worker does not certify author,
conversation, ordering, encryption or permission.

An SDK-owned render ticket must bind server, connection generation,
conversation, message/source digest and revision. Completion must independently
recheck that binding before painting or storing a derivative. Cancellation is
useful for releasing work; it does not replace the SDK's stale-result check.
Only a local job number reaches the codec Worker. Text navigation and reconnect
must not let a finished render or prepared outgoing image cross destinations.
Outgoing attachment state must remain until the SDK acknowledges the matching
send, and a newer destination/draft revision must reject an old image result.

The isolated codec and service are implemented here; the SDK ticket bridge and
App paste/attachment controls are a coordinated consumer change. Their
end-to-end completion is not inferred from codec tests.

## Bounds and recovery

Sources are limited to 256 KiB, encoded image input to 8 MiB, each serialized
reply to 2 MiB, and decoded document pixels to 640 KiB. Documents have at most
512 blocks and eight images. The existing decoder validates dimensions and
allocation limits before producing pixels; message images are at most 360×270
and composer thumbnails at most 128×128. A streaming bounded JSON writer stops
reply serialization before allocating an oversized JSON string.

The service admits at most eight jobs and 16 MiB of aggregate queued/active
source data. Only one job is posted to the codec Worker at a time. An image is
copied only after admission; transferring the copy never detaches the caller's
attachment. Every job has an eight-second deadline including queue time; worker
startup has a separate fifteen-second ceiling. A late result cannot win merely
because its timeout callback was delayed: completion checks the monotonic
absolute deadline again.

Aborting an active job terminates its Worker. Old Worker events are ignored
against the current instance. A malformed response rejects the pending queue;
a caller can retry in a fresh Worker. Ordinary invalid images return a bounded
error and permit subsequent work. A WASM trap terminates that instance rather
than reusing potentially unusable Rust execution state.

The Nix content module links with a 256 MiB maximum linear memory. This bounds
the WASM heap, not total browser process memory or the caller's original file.
JavaScript queue/reply/pixel limits are checked separately. CPU deadlines rely
on the outside adapter remaining schedulable; they are not a browser OS CPU
quota. Rendering and image work must not be moved into the TLS/voice Worker.

## Verification

`node --test tests/web_content.unit.mjs` checks production service queue and byte
budgets, active/waiting cancellation, timeout recovery, old Worker events,
forged replies, resource-bearing images, invalid RGBA and UTF-8 span boundaries.
These scheduler tests deliberately use a test Worker; they do not claim image
codec execution.

Native `nuschl-content-wasm` tests use a generated 2×2 PNG with known RGBA,
actual legacy normalization/image encoding/decoding and Rust highlighting.
`tests/web_content.browser.mjs SOURCE CODEC WRAPPER PLAYWRIGHT OUTPUT` is the
separate actual-WASM browser fixture. It independently inspects the generated
module's imports and memory maximum, then runs production content modules under
strict same-origin CSP with synthetic images, a real canvas and malicious
resource canaries. It uses the confined browser wrapper from
`tests/web_audio.py --prepare-only`; no host clipboard or physical devices are
needed. Exact native/WASM/browser results are recorded in the handoff once run.

The initial exact Nix codec build and the three native boundary tests passed.
The generated WASM was 3,741,531 bytes, with 35 initial memory pages and an
explicit 4,096-page maximum (256 MiB). Its three imports were reviewed in the
matching generated glue: throwing an error, converting a string and initializing
an externref table. No network, storage, device, random or clock import was
present.

The confined Chromium 156 run passed with the actual generated WASM, production
service and Worker. A known 2×2 image survived encoding into Mumble HTML and
legacy decoding with all sixteen RGBA bytes unchanged, then painted on a real
canvas. Plain newlines, Rust syntax colors, legacy inline code and recovery after
an invalid image passed. Script, CSS and remote-image canaries caused no resource
requests or CSP violations. Eight production scheduler/reply-boundary tests also
passed. This is isolated content proof, not yet a stock-server-to-App attachment
or browser clipboard integration claim, and no mobile browser hardware was used.
