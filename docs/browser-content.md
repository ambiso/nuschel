# Browser content boundary

`nuschl-content-wasm` runs the existing `nuschl-content` renderer with its image
feature in a dedicated browser module Worker. The UI receives typed text, spans,
code runs, formula source and RGBA pixels. It never inserts received HTML into
the DOM or sends a received URL to a browser image decoder.

The fixed loader imports `content-codec/nuschl_content_wasm.js` and its WASM from
the application's origin. No source-selected URI is fetched. The codec API has
no session, certificate, TLS, device, storage or network import. The Worker glue
receives local job numbers and message/image bytes, without server identity or
conversation metadata. Browser Workers share their origin and are not a
promise of a separate operating-system process. The reviewed glue and browser
runtime remain part of the boundary; this is not native worker confinement.

## API

`ContentService` in `web/app/src/content-service.js` belongs outside the TLS
Worker. Its Promise methods are:

- `render({source, mode}, {signal})`, where mode is `plain`, `legacy` Mumble HTML,
  or previously normalized `marked` text. The result is
  `{marked_text, plain_text, document}`. These are derivatives.
- `encodeImage(Uint8Array, serverMessageLimit, {signal})` returns
  `{html, thumbnail}`. HTML is generated by the shared encoder as a single PNG
  or JPEG data-image element, capped by the caller's server limit. It does not
  forward arbitrary supplied HTML. The thumbnail contains RGBA pixels only.
- `decodeImage(Uint8Array, {signal})` returns one bounded RGBA image block. It
  accepts supplied bytes rather than a URL, path or URI.
- `cancelAll()` revokes this facade's consumers; `dispose()` additionally prevents
  that facade's reuse. Other facades retain their own work on the shared owner.

Original plain text is retained exactly in `marked_text`/`plain_text`, including
newlines. Legacy normalization uses the same marked representation as native
clients, preserving code spans, safe link destinations and inline data images.
Typed image replies remove the shared renderer's encoded `source` property.
The initial decoded view uses message thumbnail dimensions, not full-resolution
browser image decoding. Formula rendering remains a separate feature; formulas
here carry inert source and TeX only.

## Source authority and asynchronous completion

The SDK must retain original received source and its mode as authority. A
normalized text field or rendered document must never replace authenticated
source bytes in durable history. The content Worker does not certify author,
conversation, ordering, encryption or permission.

An SDK-owned render ticket must bind server, connection generation,
conversation, message/source digest and revision. Completion must independently
recheck that binding before painting or storing a derivative. Cancellation is
useful for releasing work; it does not replace the SDK's stale-result check.
Only a local job number reaches the codec Worker. Text navigation and reconnect
must not let a finished render or prepared outgoing image cross destinations.
Outgoing attachment state must remain until the SDK acknowledges the matching
send, and a newer destination/draft revision must reject an old image result.

The browser SDK now issues the content requests and validates their completion.
`Client::receive_message` returns the exact allocated timeline serial and source
revision, including for unsaved messages; detached history admission deliberately
has no serial. No source is correlated by body or timestamp. The browser adapter
also captures the channel's process-local wire instance before later queued
channel changes. Background conversations remain eligible; selecting another
conversation does not cancel otherwise valid received content.

New IndexedDB rows store original source and an explicit `plain`/`legacy` mode.
Existing rows without a mode remain `marked`, their previously normalized
representation. No migration discards them or claims to reconstruct lost original
HTML. A cached/offline channel becoming a fresh live instance issues one new
history request and HistoryTicket; old replies/jobs are never rebound. Stock
Mumble has no durable channel UUID, so this does not strengthen the historical
identity of a numeric channel across separate connections.

Ordinary snapshots carry bounded plain derivatives, source revisions and opaque
content tokens. A validated document crosses once into the UI cache, rather than
cloning its RGBA into every snapshot. Rehydration resolves the original SDK lease
and checks its retained source digest; a worker cannot choose a new destination.
The image-picker/composer and larger-image viewer are separate consumers, and
are not implied by the broker tests. Deferred notification preview/mention
completion is still a separate parity follow-up; a placeholder is not content
on which notification or poll authority may be based.

## Bounds and recovery

Sources are limited to 256 KiB, encoded image input to 8 MiB, each serialized
reply to 2 MiB, and decoded document pixels to 640 KiB. Documents have at most
512 blocks and eight images, and at most 513 `break` blocks (the line breaks
between blocks, never two in a row, together counting at most the source size)
on a budget of their own. The desktop's worker boundary checks the same
budgets (`MessageDocument::within_limits`). The existing decoder validates dimensions and
allocation limits before producing pixels; message images are at most 360×270
and composer thumbnails at most 128×128. A streaming bounded JSON writer stops
reply serialization before allocating an oversized JSON string.

One lazy owner is shared by every ContentService facade in this page/module.
It admits at most eight jobs and 16 MiB of aggregate queued/active source data,
including a cancelled active job until its real acknowledgment. The first
admitted consumer selects the worker factory/startup configuration; later
facades cannot reset it or manufacture another owner. The factory closure is
released once consumed; there is no strong registry of idle/disposed facades.
Only active/queued jobs retain client references. Each source image is copied
only after admission, without detaching the caller's buffer.

Only one job is posted to the worker at a time. Jobs retain the original
absolute eight-second deadline, including queue time; worker startup has one
original fifteen-second ceiling. A late result or ready signal cannot win
because its timer callback was delayed: both paths check the monotonic absolute
deadline again. Shorter consumer deadlines can expire while a loader continues
to its own bound; new arrivals never extend either original deadline.

Queued cancellation releases never-posted work immediately. Active cancellation
rejects the consumer immediately but leaves a tombstone: its job/byte reservation
and original deadline remain until an exact real result/error acknowledgment.
The derivative is discarded, and the same responsive worker can serve the next
consumer. Ordinary invalid-image errors likewise reuse it. Cancellation/disposal
of one facade cannot cancel another's consumers. A healthy idle worker remains
warm for later facades, with no idle polling or automatic recreation.

A true active/startup deadline, trap/fatal, invalid owner response, post failure
or worker error permanently retires this page's shared owner. Queued consumers
are settled and listeners/timers cleaned even if terminate() throws. The owner
permit stays consumed; no new facade or repeated retry can spawn a replacement.
The numeric `bytes` diagnostic conservatively retains the retired active input's
charge, while active/queued consumer diagnostics become empty. Failed termination
is recorded separately. Diagnostics expose only detached frozen id/size/deadline
snapshots, never mutable packets, client references or settlement callbacks.

`Worker.terminate()` requests shutdown, not synchronous physical exit. Permanent
logical retirement prevents new posts/results from reentering the service while
the native worker may still run. It does not guarantee that previously submitted
work/network traffic has ceased. A future consumer should show safe source
fallback and explicit reload for this unavailable owner; automatic replacement
requires its own aggregate ownership bound. The broker turns valid current failures into inert failure documents. Temporary
queue/cache pressure offers explicit retry. A retired ContentService instead
shows reload guidance and disables impossible retry. No error invokes a parser
in the SDK or UI, and no automatic replacement owner is created.

The Nix content module links with a 256 MiB maximum linear memory. This bounds
the WASM heap, not total browser process memory or the caller's original file.
JavaScript queue/reply/pixel limits are checked separately. CPU deadlines rely
on the outside adapter remaining schedulable; they are not a browser OS CPU
quota. Rendering and image work must not be moved into the TLS/voice Worker.

## Broker, cache and outgoing images

The SDK broker bounds pending work to 128 requests and 8 MiB of logical retained
source/transport copies, with at most four requests posted to the UI. Posted
cancellation retains its SDK reservation until a UI completion acknowledgment;
that acknowledgment is distinct from the ContentService's real codec ACK and
its separately retained concurrency credit. A stalled UI cannot manufacture
unbounded replacement posts. Replies are bounded to 2 MiB before serde parsing
and independently checked for block/count/text/span/UTF-8/link/pixel limits.
Worker-selected image sources are rejected.

The UI has one 16 MiB, 256-entry derivative LRU shared by timeline and welcome
views. Serialized strings/object counts, decoded pixels and canvas/viewer copies
are conservatively charged. Mounted views pin that charge; admission under a
fully pinned budget becomes an explicit negative result instead of an automatic
rehydration loop. Disposing the bridge permanently consumes its page owner and
keeps retained view charges; disposal is not evidence that native canvases or a
Worker have exited. SDK derivative metadata is separately capped at 4096 handles
and 16 MiB of plain derivatives, with evicted model derivatives cleared. Refused
work retains only bounded retry metadata and a source digest, not another raw
source copy.

The send API is `image_begin({context, caption, attachment_revision,
draft_revision})`, using the current snapshot's mandatory `content_context`.
It returns a ticket and remaining HTML/input budgets. Only the UI/content codec
receives selected file bytes. `image_send({ticket, attachment_revision,
draft_revision, html, thumbnail})` accepts a fixed PNG/JPEG data-image element
and validated thumbnail pixels, never arbitrary HTML. The SDK combines only its
captured, escaped caption into the same message. Navigation, connection/channel
replacement, own/peer presence, revisions and current limits are rechecked at
actual enqueue. `image_cancel(ticket)` revokes the matching lease. Failure keeps
the draft/attachment with its consumer.

The fixed image grammar allows a conservative stripped-src text-budget check
without an HTML parser in the SDK; the separate whole-image UTF-16 cap and
256 KiB local wire ceiling also apply. `sent_to_transport` means local transport
admission, not a Mumble server delivery acknowledgment. TLS writes preserve
rustls's 64 KiB buffer and drain between partial plaintext writes. Each complete
application frame remains contiguous; bounded TLS chunks/queues and a combined
WebSocket-buffer preflight prevent unbounded pending transport. Local Sent/echo
events bind to their entire frame's successfully enqueued record boundary.
Later partial failure closes that connection without retrying a partial frame;
independently received peer text remains valid. Dropped unsent TLS records never
advance the admitted/drained boundary.

## Verification

`node --test tests/web_content.unit.mjs` checks production service queue and byte
budgets shared across facades, active cancellation tombstones/real ACK reuse,
queued cancellation, absolute startup/active deadline races, no-replacement
retirement, failed terminate/factory/post paths, detached diagnostics, forged
replies, resource-bearing images, invalid RGBA and UTF-8 span boundaries.
These scheduler tests deliberately use a test Worker; they do not claim image
codec execution.

Native `nuschl-content-wasm` tests use a generated 2×2 PNG with known RGBA,
actual legacy normalization/image encoding/decoding and Rust highlighting.
`tests/web_content.browser.mjs SOURCE CODEC WRAPPER PLAYWRIGHT OUTPUT` is the
separate actual-WASM browser fixture. It independently inspects the generated
module's imports and memory maximum, then runs production content modules under
strict same-origin CSP with synthetic images, a real canvas and malicious
resource canaries. It uses the confined browser wrapper from
`tests/web_audio.py --prepare-only`; no host clipboard or physical devices are
needed. Exact native/WASM/browser results are recorded in the handoff once run.

The initial exact Nix codec build and the three native boundary tests passed.
The generated WASM was 3,741,531 bytes, with 35 initial memory pages and an
explicit 4,096-page maximum (256 MiB). Its three imports were reviewed in the
matching generated glue: throwing an error, converting a string and initializing
an externref table. No network, storage, device, random or clock import was
present.

The confined Chromium 156 run passed with the actual generated WASM, production
service and Worker. A known 2×2 image survived encoding into Mumble HTML and
legacy decoding with all sixteen RGBA bytes unchanged, then painted on a real
canvas. Plain newlines, Rust syntax colors, legacy inline code and recovery after
an invalid image passed. Script, CSS and remote-image canaries caused no resource
requests or CSP violations. Eight production scheduler/reply-boundary tests also
passed. This is isolated content proof, not yet a stock-server-to-App attachment
or browser clipboard integration claim, and no mobile browser hardware was used.


## One-owner retirement evidence

The focused service suite now passes 17 checks:

```sh
node --test tests/web_content.unit.mjs
```

Tests load the actual production service in fresh test VM module realms; there
is no public production reset/owner-replacement option. They exercise global
eight-job/16 MiB limits, first-factory/options behavior, canceled active credit
retention, exact ACK reuse, disposal scoping, delayed timer/ready/result races,
throwing termination and diagnostic reads that cannot mutate capacity or settle
consumers. The protocol validation and invalid-image recovery gates remain.

The original actual-WASM image/code/legacy/canvas/canary fixture still passes.
`tests/web_content_retirement.browser.mjs SOURCE CODEC WRAPPER PLAYWRIGHT OUTPUT`
adds ordinary fault tasks to the served worker prefix for testing, then uses the
real already-initialized WASM realm. Healthy cancellation and disposal reuse one
worker; an eight-job synchronous cross-facade fill rejects the ninth. During a
12-second blocked worker task, a cancelled 8 MiB active image plus queued 8 MiB
retains 16 MiB until the original 8-second deadline. Retirement settles consumers,
reserves the active 8 MiB conservatively, and rejects 20 new facades without
another post or worker. Normal and throwing-terminate modes are separate fresh
pages; no physical-exit acknowledgment is asserted.

In the throwing-terminate case, the actual old worker continues and returns a
real WASM invalid-image error after retirement. The service ignores that late
reply and never reopens its reservation. Both modes pass under same-origin CSP,
with original text/newlines, typed code/image output, exact RGBA, invalid-image
reuse, resource canaries and no host devices. The generated module still has
35 initial/4096 maximum memory pages (256 MiB); its bytes match the previously
reviewed codec. This bounds WASM linear memory, not total process/caller memory.

Final proofs, exact source/artifact hashes and invocations are recorded in
`~/.cache/nuschl-content-retirement/handoff.json`; `browser-final/proof.json`
contains the deadline/late-reply observations and `positive/proof.json` retains
the original codec/canary gate. These scoped producer checks do not establish
full attachment/broker operation or platform-independent browser scheduling.

The private scheduling state machine is shared with formula rendering in
`worker-owner.js` (checkpoint `87fae40c`). This shares implementation, not worker
ownership, input validators, budgets or caches. The content facade still has one
distinct page owner, eight jobs / 16 MiB, original eight-second job and
fifteen-second startup deadlines, and no automatic fatal-owner replacement.
After extraction all seventeen content units and the complete actual-WASM
code/image/canary plus normal/throwing-termination browser proofs pass again;
see `~/.cache/nuschl-math-retirement/content-browser/proof.json`.

## Broker integration evidence

The focused client-WASM suite covers source/revision/receipt admission, raw-mode
history, canceled/stalled SDK transport credit, typed reply rejection, image
leases/caps, partial/no-progress TLS output and transport-pressure admission.
Its owned TLS-relay fixture sends a 200,000-character text and a valid synthetic
PNG data-image above 200,000 characters in one pending batch, then checks exact,
separate received messages. It exercises TLS and framing rather than an image
codec or a production server. The optional stock-Murmur native test is explicitly
ignored unless invoked with its owned `NUSCHL_TEST_MURMUR` executable; absence of
that environment is an error when explicitly invoked, never a passing test.

`tests/web_broker.browser.mjs SITE RELAY HOST PORT OUTPUT.png` drives the actual
built App through an owned loopback relay/stock Murmur in a device-free Chromium
wrapper. One scene delays a real codec result across reconnect: the old SDK
ticket is refused, a new history request restores the row, and only one codec
Worker exists. Another substitutes a permanently stalled Worker and checks
safe failure documents, explicit reload guidance, no privileged render fallback,
no replacement Worker and no microphone capture. The separate desktop/mobile
Markdown smoke checks live and IndexedDB-restored newlines, blank lines, code
highlighting, safe links and resource canaries. These are confined Chromium
results, not physical mobile or OS process-isolation claims.
